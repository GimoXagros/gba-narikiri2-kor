## 퀘스트 목표물과 전투 정보창

퀘스트 대사가 이름 양옆에 붙이는 『』는 각각 2바이트다. v1.1c의 두 코드 경로에서 압축된 괄호를 그대로 읽었다. 두 경로가 원래 바이트를 읽도록 수정했다. 가상 mGBA에서 같은 저장과 버튼 입력으로 숲의 사냥꾼이 묻는 **『엘릭서』 찾고 있어?** 와 목적지 안내의 **『사냥꾼의 숲』** 을 확인했다. 장로의 첫 의뢰 수주와 민트의 숲 입장 대사도 확인했다. CPU 시험에서는 유효한 아이템 157종의 이름과 괄호를 대조했다.

TEST01에는 별도의 전투 정보창 깨짐이 있었다. 스펙터클즈로 적을 조사할 때 압축된 적 이름과 세 항목을 그리기 직전에 풀도록 수정했다. 숲에서 나이트 레이드의 이름과 공격·강함·약함 항목, HP, 속성 아이콘을 확인했고 B를 눌러 전투로 돌아갔다. 가상 VBA-M에서는 처음 마을에 들어간 뒤 SELECT로 메뉴를 열 때 실행되던 ARM7 비호환 덧셈 명령 두 곳도 수정했다.

## 그래픽과 명칭

전투의 TARGET과 결과 화면의 BONUS·EXP·GALD는 일본어판의 타일을 복원했다. 첫 전투와 동굴 전투에서 표적 화살표, 글자 팔레트와 결과 수치를 대조했다. 도감 087·088은 밀정, 103은 인챈터, 104는 인챈트리스, 128은 유랑 예술가, 129는 물 곡예사로 교정했다. 도감 번호와 내부 직업 번호, 수정한 저장 위치는 `issue25-names.csv`에 기록했다. 내부 JOB_087·088의 암석투사 표기도 별도로 확인했다.

## 재현 빌드

개발자는 v1.1c 빌드 안내에 따라 기준 ROM을 먼저 만들고 고정된 비공개 입력과 함께 다음 명령을 실행한다. 입력의 해시는 빌더에서 검사한다. 새 출력 폴더의 BUILD_RESULT.json에 각 변경 구간의 소유자와 전후 해시, 바인딩별 인코딩을 기록한다.

```text
python tools/build_issue24_25.py --japanese Japanese.gba --v11c Xagros_Narikiri2_KOR_v1.1c.gba --master JP_KO_MASTER_UTF8.csv --link LINK.json --components BUILD.json --corpus reviewed-dialogue-data.json --out new-candidate
```

## My Boy Premium에서 확인하는 순서

1. ROM 해시와 My Boy 버전을 기록하고 일반 저장의 사본을 사용한다. 첫 의뢰 수주 직전에 별도 슬롯에 저장한다.
2. 장로의 의뢰를 수락한 뒤 마지막 목표물 확인 대사와 사냥꾼의 숲 입장 직후 대사를 캡처한다. 숲의 사냥꾼에게 말을 걸어 『엘릭서』와 『채집장』이 보이는 문장도 확인한다.
3. 다른 의뢰를 받을 때는 의뢰인·목표물·지역과 이름 뒤의 조사까지 함께 기록한다.
4. 숲 전투에서 스펙터클즈를 사용한다. 파란 정보창의 적 이름, HP, 공격·강함·약함을 확인하고 B로 닫아 전투를 이어간다.
