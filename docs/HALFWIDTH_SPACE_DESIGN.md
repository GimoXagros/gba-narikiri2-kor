# 반각 공백 구현과 보존 범위

이 문서는 반각 공백의 구현 계약을 설명한다. 배포 여부와 최종 파일의 검증 결과는 해당 버전의 검증 기록에서 확인해야 한다.

## 표시 원칙

큰 글자의 일반 단어 간격은 12px에서 6px로, 허용된 소형 문자열 경로의 단어 간격은 8px에서 4px로 줄인다. 글자 자체의 폭과 모양은 바꾸지 않는다. 소형 문자열 하나의 끝은 기존 8px 격자에 맞추므로, 서로 다른 출력 호출 사이의 간격까지 항상 4px가 되는 것은 아니다.

숫자 열, 들여쓰기, 이름 입력판처럼 위치가 의미를 가지는 공백은 별도 정책으로 보존한다. 사용자 이름과 저장 데이터는 원본 그대로 읽는다. 서식 문자열의 `%s` 인수가 RAM이나 저장 데이터에서 온 경우에도 단어 공백을 일괄 치환하지 않는다.

## ROM과 문자열 위치

ROM 크기는 8,388,608바이트를 유지한다. 10,371개 텍스트 바인딩의 포인터 저장 위치와 포인터 값, 문자열 시작 위치를 기존 기준선과 대조한다. 압축 문자열을 다시 만들 때도 원래 슬롯 안에 넣고, 슬롯을 넘는 결과는 거부한다.

추가 처리 코드는 검증된 소유 영역에만 배치한다. 일부 영역은 이미 종료된 압축 문자열 뒤의 여유 공간이다. 이 경우 원본 슬롯의 경계, 현재 압축 데이터의 끝, 다른 기록과의 중첩, 실제 디코더의 읽기 범위를 확인한다. 단순히 같은 바이트가 반복되거나 참조 검색 결과가 없다는 이유만으로 빈 공간으로 인정하지 않는다.

## 소형 문자열 처리

허용된 ROM 문자열만 임시 버퍼에서 준비하고 반각 공백 표식을 넣는다. 원본 문자열이나 포인터를 이동하지 않는다. 글리프의 매개변수 바이트와 문자열 제어 코드를 구분하며, 지원하지 않는 제어문이나 화면 조건은 원래 처리 경로로 돌린다. 숫자 전용 서식과 정렬용 공백은 원래 처리기를 사용한다.

문자 모양을 저장하는 캐시의 슬롯과 화면에 남아 있는 글자의 관계도 유지해야 한다. 특히 숨겨진 개발용 목록은 일반 플레이 목록보다 많은 행을 동시에 표시한다. 실제 64슬롯 조건에서 필요한 합성 글자 수가 이를 넘는 경로에는 일반 목록의 반각 처리기를 강제로 적용하지 않는다. 이 예외는 공백 조사표에 따로 기록한다.

## 검증 범위

검증은 다음 증거를 구분한다.

- 파일 검사: 정확한 입력과 결과 해시, ROM 크기, 포인터·문자열 위치, 변경 영역, 패치 재적용 결과.
- CPU 검사: 실제 설치된 코드의 출력 픽셀, 좌표, 레지스터·스택, 버퍼 경계와 원래 처리기로의 복귀.
- 가상 실행: 고정 입력에 따른 목록 전환, 화면 진행, 게임 내 저장과 새 실행에서의 불러오기.
- 실기·전체 진행: 가상 실행과 별개의 검증이며, 실행하지 않은 범위는 통과로 기록하지 않는다.

성능은 원래 입력 간격과 목록 표본을 유지한 채 게임 프레임으로 측정한다. 화면 생략 설정이나 조작 간격을 바꿔 결과를 개선하지 않는다. 개별 수정본의 통과 기록은 바이트가 다른 최종본에 자동으로 승계하지 않는다.

추가 기계어는 GBA의 ARM7TDMI 명령 집합에 맞아야 한다. 범용 CPU 시험기가 후대의 명령도 받아들이는 경우가 있으므로, CPU 비교 통과만으로 호환성을 인정하지 않는다. 실행 가능한 건너뛰기 명령에는 ARMv4T에서 유효한 `MOV r8,r8` 인코딩을 사용하고 실제 GBA 코어의 실행 결과도 확인한다.

검증용 ROM·저장·저장 상태·전체 대사 자료는 비공개 로컬 자료로 관리한다. 공개 배포물에는 패치, 적용 도구, 설명과 검증 요약만 포함한다.
