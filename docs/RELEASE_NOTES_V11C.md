# v1.1c — 기술 설정 제목 여백 수정과 오디오 원인 검증

기술 버튼 설정 화면의 제목을 화면 상단에서 4px 아래로 옮겼습니다. 기존 글자 획은 모두 남아 있었으나 Y=0 배치 때문에 상단에 붙어 잘린 것처럼 보였습니다. 글꼴을 새로 그리지 않고 배치 명령만 고쳤습니다. v1.1b와 실제로 다른 ROM 바이트는 `0x134C6` 한 곳입니다.

결과 ROM은 8,388,608바이트이며 SHA-256은 `bf9e425dc172fb36b0f3ab221a14299898768a8bf5e7e7c36feaf7242f86334c`입니다. BPS는 383,088바이트, SHA-256 `18407507b181b0e24d53313e03b032f0140fdf111e804901ae69c11cfb7d0d98`입니다. 원래 포인터·문자열 시작 10,371개와 저장 형식을 유지합니다.

## 오디오 조사 결과

기준선과 달랐던 스테레오 프레임 1개는 시험용 mGBA 코어의 FIFO 샘플 위치 계산이 타이머 처리 지연을 반영하지 않아 발생했습니다. 동일 소스·빌드 조건에서 해당 계산 한 줄을 수정한 별도 참조 코어로 v1.1a·v1.1b·v1.1c를 실행하자 1,500,002개 스테레오 프레임이 모두 같았습니다. 별도 VBA 코어의 동일 경로에서도 세 버전의 PCM 전체가 일치했습니다.

**ROM의 음원·오디오 코드는 수정하지 않았고 설치된 에뮬레이터도 바꾸지 않았습니다. 기존 mGBA 코어에는 같은 1샘플 차이가 남습니다.** 참조 코어 수정의 원인 추적, 소스 패치 및 재현 방법은 [오디오 기술 기록](AUDIO_TIMING_V11C.md)에 있습니다. 이는 청취 평가나 상류 채택을 의미하지 않습니다.

## 최종 해시 검증

- 원본과 명시한 입력으로 별도 소스 폴더에서 ROM·BPS 바이트 동일 재빌드.
- 10,371개 포인터·시작 위치, 보호 문자열 45곳과 8MiB 크기 확인. 최종 ROM에서 디코더 CPU 호출 8,947건 및 대사집 10,371행 읽기 검증.
- 제목 원래 픽셀·VRAM·팔레트 보존. 전투 경로 23화면 중 22화면 동일, 나머지 제목 화면만 예상 영역 변경. 0·60·600프레임 대기 상태 확인.
- 기본·혼합 이름 저장의 두 차례 새 프로세스 불러오기, 다시 저장 후 불러오기, 중단 저장 생성·재개·소비 확인. 기존 입력 저장은 보존.
- 아래 고정 목록 시험은 동일한 입력 간격과 기존 RAM fixture를 사용한 가상 실행입니다. 자연 해금·실기 성능 시험과 구분합니다.

총 7,330회에서 미완료 이동은 0건입니다. 공개 CI는 ROM 없는 계약 검사이며 가상 실행과 구분합니다. [검증 계약](../verification/v1.1c.json)과 [관문별 증거](../verification/v1.1c-evidence.json)는 최종 해시에 연결합니다.

펍 로즈 진입과 민트 대사 지점의 최종 ROM 전용 SGM을 만들고, 역변환 및 새 VBA 가상 실행에서 다음 대사 진행을 확인했습니다. 데스크톱 SGM 읽기는 미검증입니다. 기술 설정으로 가는 입력 경로는 VBA에서 v1.1b·v1.1c 모두 전투 전환 뒤 검은 화면에 도달했고 40개 캡처가 같았습니다. 해당 VBA 전투 경로는 통과로 처리하지 않았으며 제목 수정 확인은 mGBA의 정상 진행 경로에 한합니다.

## 남은 범위

최종 v1.1c의 실기·청취·전체 분기·장시간 전편 진행·통신은 미검증입니다. 일본어 ROM의 동등한 기술 설정 장면은 같은 입력 경로로 확보하지 못했으며 일본어 화면과의 시각적 동등성을 주장하지 않습니다. 기존 이슈 #4와 이전 릴리스 기록은 유지합니다. 사용자 요청에 따른 조건부 배포이며 최종 파일 직접 수락은 아직 보고되지 않았습니다.
