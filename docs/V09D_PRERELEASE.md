# v0.9d 프리릴리즈 검증

타이틀의 **교환**만 기존 글꼴 그래픽을 사용하던 문제를 수정했다. **처음부터·이어하기·중단부터**를 비교 대상으로 삼고 같은 달무리 기본 8×8 글리프, 잉크 1, 외곽선 9, 세로 위치 4로 맞췄다. 중단부터는 이미 같은 글꼴이므로 불필요하게 다시 쓰지 않고 픽셀 일치와 실제 불러오기를 확인했다.

## 원인과 소유 범위

리소스 테이블 `0x3768F8`의 12번, 상대 포인터 저장 위치 `0x37692C`, 원본 그래픽 위치 `0x37E584`. 기존 RL 스트림은 223바이트를 읽어 384바이트를 생성한다. 런타임 OAM의 16×16 조각 3개는 메모리 순서가 **중앙/오른쪽/왼쪽**이며 OBJ VRAM `0x06014600..0x06014780`을 소비한다.

같은 글꼴로 만든 교환 그래픽을 이 순서로 배치해 124바이트 VRAM용 LZ 스트림으로 넣었다. 최종 쓰기 범위는 `[0x37E584,0x37E600)`이다. 기존 슬롯보다 작으므로 포인터·팔레트·OAM·화살표·로고·저작권 표시 변경은 없다. 이전 테스트판 대비 바뀐 바이트는 109개, v0.9c 대비 누적 변경은 1,129개다. 나머지 바이트와 EEPROM/글꼴/음성 영역을 대조했다.

`config/title_trade_glyphs.json`의 교/환은 달무리 커밋 `897f0e71224d9964a84b888f2596b2bfd7f98def`의 원생 비트맵이다. 제품 빌드는 고정된 생성 결과의 파일 해시와 비트맵 행을 검사한다. 기존 이어하기·처음부터·중단부터의 압축 해제 결과도 같은 생성기의 비트맵으로 만든 기대치와 전체 일치한다.

## 최종 결과와 실행 검사

최종 ROM: `69c5a3e22e00bcacfbaaa7eb28f2efc7d06c8ef37a646ac7236bc78bf76d4012`, 13,107,200바이트.

일본어 원본용 BPS: `efcbbcc5b0973ecf27ed73e4223211a9875cac0d4ba6192e26e1ea535ac6bcb5`, 4,881,466바이트.

ZIP: `880cf6e64d1688e8905dd7a8f2f422cfffe8a7862a2127bcba5ef287b4d9022f`, 407,172바이트. 두 번 생성한 ZIP이 같고, 새 폴더에 풀어 동봉 도구만으로 일본어 원본을 적용한 결과도 최종 ROM과 같았다. 기존 출력·BETA3·v0.9c·변조 원본·손상 패치는 출력 없이 거부했다.

에뮬레이터는 mGBA libretro `0.11-219-e31759b`, HLE BIOS이며 코어 해시는 `verification/v0.9d.json`에 고정한다. 수동으로 보정하지 않은 실제 프레임과 메모리 덤프는 로컬 증거로 보존한다.

- 저장 없음: 처음부터/교환, 일반 저장: 이어하기/처음부터/교환, 중단 저장: 중단부터/처음부터/교환을 확인했다. 8개 선택 화면에서 그래픽 로드 결과, OAM, 팔레트, 변경 영역 밖의 모든 픽셀을 검사했다.
- 교환 화면 진입·취소·타이틀 복귀를 확인했다. 실제 두 기기 사이 통신 성공을 뜻하지 않는다.
- 중단 저장 `8573c0f598cdf0d73d885da4e2e11f4554b7713bd1f46666dcdc88b137d9b906`을 콜드 부팅으로 읽고, 중단부터를 선택해 칠흑의 갱도 입구에서 재개했다. 재개 화면과 소비된 EEPROM 결과는 수정 전과 일치한다. 다른 ROM의 savestate는 사용하지 않았다.
- 최종 해시에서 Namco 전체 프레임 원본 일치와 대열 선택·이동·확정·복귀 검사 15개를 다시 통과했다.
- 최종 해시에서 RAM 변경 없이 테스트 세이브의 아이템 156종/157화면, 몬스터 142개·코스튬 200개·인물 22개 도감 목록 및 상세 진입·복귀를 다시 확인했다.
- 공개 계약 49개, 일본어 적용 계약 7개, 타이틀 소비자 계약 3개, 총 59개 통과. 실패·오류·건너뜀 0. 과거 전체 150개 실데이터 시험을 이번에 재실행했다고 주장하지 않는다.

선택 항목 수를 처음에 중단 저장 4개로 가정한 탐색에서는 마지막에 중단부터로 돌아왔다. 최종 증거는 실제 3개 항목과 교환 진입을 다시 실행한 경로로 한정한다.

## 전체 제품 재현

기존 한글화 결과 파일을 제품 빌드 입력으로 요구하지 않는다. 기존 번역·수정 소스와 고정 BETA2/BETA3/일본어 입력으로 번역 및 저장 구성 요소를 재생성한 뒤, Namco·대열·타이틀 수정까지 하나의 빌드로 합친다. 사용자가 배포 패치를 적용할 때 필요한 입력은 일본어 원본뿐이다.

독립 글꼴 체크아웃과 고정 의존성을 준비하는 방법은 `BUILDING.md`의 달무리 설정을 따른다. 이번 환경은 Node 24.19.0, pnpm 7.33.7의 frozen lockfile, Python 3.14.6이다. 새 체크아웃에서 TypeScript를 컴파일했으며 채택한 글리프는 고정 생성 결과와 대조했다. 선택적인 WOFF2 네이티브 모듈은 Windows SDK 부재로 빌드되지 않았지만 이 비트맵 경로에서 사용하지 않는다.

```powershell
python tools/build_v09d.py --beta2-reference "BETA2.gba" --beta3 "BETA3.gba" --japanese "Japanese.gba" --out-dir output/v09d-A
python tools/build_v09d.py --beta2-reference "BETA2.gba" --beta3 "BETA3.gba" --japanese "Japanese.gba" --out-dir output/v09d-B
python tools/package_v09d.py --japanese "Japanese.gba" --target output/v09d-A/Xagros_Narikiri2_KOR_v0.9d.gba --output output/Xagros_Narikiri2_KOR_v0.9d_JP_PACKAGE.zip
```

별도 두 제품 빌드 결과가 동일하다. 패키지 도구는 `verification/v0.9d.json`의 정확한 결과 및 패치 해시와 준비 상태가 일치해야 동작한다. ZIP에는 적용 도구·BPS·검증 및 라이선스 고지만 포함한다. ROM·SAV·BIOS·런타임 그림은 공개하지 않는다.

이번 배포는 사용자 요청에 따른 **v0.9d 프리릴리즈**다. 이전 릴리즈 파일은 덮어쓰지 않으며 실기·장시간 전체 진행 과제 #4는 유지한다. 이전 테스트 세이브는 호환되며, 처음 Namco와 대열 결함의 상세 원인은 `V09D_GRAPHICS_TEST.md`에 남긴다.
