# v0.9d 그래픽 수정 및 일본어 원본용 테스트 패키지

이 문서는 최종 프리릴리즈 전 테스트판의 이력이다. 당시 도구는 커밋 `bcbb558f434d917526438e4643387354151d7faa`에 보존된다. 최종 v0.9d는 [프리릴리즈 검증 기록](V09D_PRERELEASE.md)을 참조한다.

2026-09-13 사용자 요청: 표지 교체, 첫 Namco 화면 원본 복구, 대열 위치 변경 그래픽 수정, 전체 아이템·도감 테스트 세이브. 추가 요청으로 적용 입력을 일본어 원본으로 전환하고 표시 명칭을 Xagros의 한글화 패치로 변경했다. 저장소는 동일한 ID `1356107995`를 유지하며 `GimoXagros/gba-narikiri2-kor`로 이름을 변경했다. FFR 팀의 기존 번역 기여는 `CREDITS.md`에 남긴다.

## 기준과 수정 범위

시작 커밋은 v0.9c 태그의 `995c6eefb0de5bda49e730bd05997f9d950c0813`. 기존 배포 파일과 태그는 수정하지 않는다.

| 자료 | SHA-256 |
| --- | --- |
| 일본어 AN9J | `a92c0f6dbb5c013b47b7178e23d81663e3952a10df7b1f68967ebf7bb3b98eb7` |
| BETA3(071102) | `c6d7a401aa2a22362b2d27d0d31632cb2180a86b094788815d949b84c7fc944d` |
| v0.9c 결과 | `d761088a8549cb5bc60a2f03a4b78eea5282dbc17ed5da4ef1de27da4ad8d4d4` |
| 이번 테스트 결과 | `e9dbed3a744100b02ec1e0a67c153dda850d5c95fcfe32803008397ae6c9a04a` |

v0.9c 대비 수정은 아래 두 영역의 총 **1,020바이트**이다. 그 밖의 모든 바이트를 대조하여 일치를 확인했다. EEPROM 코드, 글꼴·음성, 번역, 헤더와 포인터를 변경하지 않았다.

1. `[0x37FC34, 0x3800B2)`의 Namco 하단 그래픽을 일본어 원본의 RL 스트림으로 복구한다. 압축 1,150바이트, 출력 1,440바이트. 제목 리소스 테이블 `0x3768F8`의 18번 항목이며 다음 리소스 `0x3800B4`를 침범하지 않는다.
2. `0x3AC1D8`의 대열 선택 테두리 압축 형식 바이트를 `00 → 30`으로 복구한다. 원본과 BETA3/v0.9c의 133바이트 스트림에서 차이는 이 한 바이트뿐이다. 압축 해제 결과는 128바이트, OBJ VRAM 목적지는 `0x06011B00..0x06011B80`이다.

대열 결함은 **BETA3에서 이어진 오류**다. 디코더 `0x080033D4`는 헤더 상위 니블이 1이면 LZ, 3이면 RL 경로로 분기한다. 0인 경우 압축 해제를 건너뛴다. 잘못된 경우 이전 그래픽 데이터가 선택 테두리에 나타났다. 원본·BETA3·v0.9c를 같은 호환 배터리 세이브에서 비교했으며 OAM과 해당 팔레트는 같고 선택 테두리 VRAM만 달랐다. 복구 후 원본 128바이트와 일치했다.

사용자 스크린샷의 화면 전체가 흰색으로 보이는 현상까지 동일하게 재현한 것은 아니다. PC에서 재현하고 수정한 결함은 대열 선택 테두리의 그래픽 손상이다. 완성 스크린샷을 덧칠하거나 보정하지 않았다.

## 실제 실행 검증

코어: mGBA libretro `0.11-219-e31759b`, SHA-256 `0d3177c927d791fef897f735d88db3646f7932d02054af108619c6df4e1597f1`, HLE BIOS. 정확한 최종 ROM에서 실행했다.

- 전원 투입 100프레임의 Namco 화면 전체 픽셀이 일본어 원본과 일치했다.
- 대열 선택, 좌우 이동, 확정, 취소 후 메뉴 복귀, L/R 담당 변경, 재진입을 확인했다. 선택·이동·확정의 OAM과 팔레트는 일본어 원본과 같고 선택 그래픽도 원본과 일치한다.
- 초기 비교에서 v0.9c 전용 이름 인코딩이 든 세이브를 원본/BETA3에 넣어 메뉴 진행이 달라진 기록은 대열 비교 증거에서 제외했다. 최종 3종 비교는 호환 세이브 SHA-256 `8fcb676bd49121976f20a054b262f04255429852857c0be382cbcaca44c1b54f`를 사용했다. 다른 ROM의 savestate는 사용하지 않았다.
- 아이템 156종 전체: 157개 화면 샘플, 이름 글리프와 기본 글꼴 8,192바이트 유지 검사 통과.
- 도감 목록 이름: 몬스터 142개, 코스튬 200개, 인물 22개 전체 통과. 각 항목의 상세 진입·복귀도 실행했다. 이번 시험은 전체 번역을 새로 교정했다는 뜻은 아니다.

## 테스트 세이브

원본 개인 저장을 덮어쓰지 않고 별도 초반 저장을 복사해 사용했다. 아이템 1~156번에 각 1개를 설정하고 몬스터 발견·조사, 코스튬 발견, 인물 도감 비트만 해금했다. 스토리 플래그는 보존했다. 그 후 **게임 자체 저장 메뉴로 EEPROM에 기록**하고 새 코어로 전원 재실행하여 모든 값의 보존을 확인했다.

8 KiB 배터리 세이브 SHA-256: `182746f4c9af1b7c174e28369879f99993832e54eca2bae9321dcc7e5a991aa4`.

위 도감·아이템 전체 검사에서는 `--require-unlocked-save`로 해금 상태를 요구하며 RAM 변경 없이 이 세이브를 읽었다. 해금 시점은 테스트용 편집이며 자연 진행 해금 증거가 아니다. 모든 코스튬 보유·레벨·기술 습득·스토리 완료는 변경하지 않았다. 이 세이브는 사용자 로컬 전용이며 공개 패키지에는 넣지 않는다.

## 패키지 검증과 재현

일본어 원본 → 최종 테스트 ROM BPS 크기: 4,881,483바이트.
SHA-256: `e483eb112ba2b0480aa6fd0e7eeb69b14165473bf0741c672b9a06145c8f7c68`.

ZIP 크기: 405,781바이트.
SHA-256: `727587127156aa2ec0c5bc5d8aa852d06093b54068253968b1df27c378cc4491`.

별도 두 디렉터리에서 ROM과 ZIP을 각각 재생성해 바이트 일치를 확인했다. 패키지를 새 경로에 풀어 동봉 도구만으로 일본어 원본을 적용한 결과도 같은 ROM이다. 기존 파일, BETA3, v0.9c, 동일 크기 변조 원본, 손상 패치는 출력 없이 거부한다. 합성·파일 안전 테스트 **49 + 7 = 56개** 통과, 실패·오류·건너뜀 0. 과거 전체 150개 실데이터 시험을 이번에 다시 실행했다고 주장하지 않는다.

```powershell
python tools/build_graphics_test.py --baseline "v0.9c.gba" --japanese "Japanese.gba" --out-dir output/graphics-test
python tools/package_japanese_test.py --japanese "Japanese.gba" --target output/graphics-test/NARIKIRI2_v0.9d_graphics_test.gba --output output/Xagros_Narikiri2_KOR_v0.9d_test_JP_PACKAGE.zip
python tools/run_v09c_public_tests.py
python -m unittest discover -s tests -p test_japanese_application.py -v
```

개발용 재생성에는 검증된 v0.9c를 사용하지만, 사용자의 패치 적용 입력은 일본어 원본뿐이다. 실기·장시간 전체 진행은 미검증이며 이슈 #4를 유지한다.
