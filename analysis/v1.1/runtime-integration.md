독립 검수자가 재계산했다. 빈 파일·잘못된 길이·32KiB 파일의 잘못된 뒷부분 등
5건은 변환 도구에서 거부한 시험으로 별도 분류한다. 자료 집계기의 항목 누락
검사도 보강해 실제 전체를 재실행했다. 체크섬 알고리즘의 모든 오류나 임의의
손상 파일·강제 저장까지 안전하다는 주장은 하지 않는다.

## 2026-10-11 성능 통합과 최종 이미지 주소 검사

ca83 후보는 여섯 코드 영역 합계 2,006바이트 안에서만 1,738바이트를 변경한다.
그 밖의 변경은 0이며 기존 텍스트 포인터 10,172개·시작 9,246곳·한국어 복원값을
최종 이미지에서 다시 검사해 모두 일치했다. 새 ROM/RAM 공간이나 저장 필드는
추가하지 않았다. 마지막 상점 자원·이름 비교 코드·인접 대사 코드는 그대로다.

실제 분기 163개·명령 813개·PC 상대 읽기 41곳과 고정 배치 52항목을 검사했다.
새 타일 코드의 연속 변수 읽기는 0300004C부터 03000058 직전까지 정확히
12바이트를 r1/r2/r3으로 읽는다. 검사기는 물리적 준비 명령·소비 명령과 분기의
우회를 확인하며, 네 번째 단어 읽기·다른 기반 레지스터·준비 명령을 건너뛰는
변조본을 거부한다. 기존 개별 읽기 방식도 유지하여 이전 후보 검사와 대조했다.
공개 회귀 23개가 최적화 실행 옵션 `-O`에서도 통과했고, 실제 ca83 변조 사본
11개를 거부했다. 이는 명시한 읽기·분기·소유 영역의 검사 범위이다.

같은 ROM·코어·저장·입력으로 여섯 경로를 각각 5회 측정했다. 이전과 같은
`sorted(intervals)[floor((N-1)*0.99)]`를 사용하며 긴 구간도 제외하지 않았다.

## 2026-10-11 최종 이미지의 확장 주소 모양 재분류

독립 검수자는 ca83의 실제 최종 바이트를 다시 읽어, 일본어 원본과 다르고
`[08800000,0A000000)` 값 모양인 정렬된 단어 866개를 조사했다. 861개는
ac0와 같고 새 5개는 실제 코드 진입점에서 도달하는 Thumb 명령 쌍이었다.
압축 내용 761개, 그래픽 내용 96개, 메뉴의 두 길이 필드 1개, PCM 표본 1개,
Thumb 명령 쌍 7개로 분류됐다. 이 숫자는 값 모양 조사이며 전체 참조의
도달 가능성을 증명하는 숫자가 아니다.

기존 보고서에서 압축 내용으로 분류한 `B9498:08C24607`은 실제로
`mov r7,r0; lsrs r2,r0,#3` 명령이었다. 분류기를 고쳐 원래 위치의 디코더
128바이트 전체가 조립 결과와 일치할 때만 그 한 단어를 명령으로 인정한다.
명령·다른 바이트·영역 끝·이름·위치를 바꾼 반례는 이 분류를 얻지 못한다.
영역 이름만으로 실행 코드를 압축 데이터로 처리하지 않는다. ROM 바이트를
수정하는 변경은 아니다.

23개 native 훅의 실제 목적지는 모두 8MiB 안이며 보존 기준선과 같다.
과거 재배치 리터럴 68곳 중 60곳은 바이트가 같고, 다시 작성한 코드에 속한
8곳은 과거 저장 위치 대신 현재 코드의 PC/ADR/LDM·분기 검사로 확인했다.
그래픽 96개는 자원 영역 전체, PCM은 헤더·표본·참조 전체를 비교했다.
`0A/0C` 카트리지 미러 주소는 같은 카트리지 오프셋으로 해석했으며,
예를 들어 `0C2BCFE0`을 잘려 나간 `08C...` 확장 주소로 취급하지 않았다.

LINK의 고정 `remaining_gates` 문구와 21,602개 `adopted_carryover_open`
이름은 이후 검증 결과를 읽어 계산한 미분류 포인터 수가 아니다. 검토한
실제 변경 참조·훅·자원표 범위에서 새 축소로 생긴 구체적인 미해결 주소는
찾지 못했다. 임의 계산 경로·전편 자연 진행·실기 안전성이나 위 입력 회귀를
해결했다는 의미는 아니다. 과거 원본부터의 미지원 selector 범위와 채택본의
RL32/43 연구 기록도 유지하며, 확인된 실패를 통과로 바꾸지 않는다.

중간 배치의 여유 공간도 최종 상태와 구분했다. `layout.free=416`은 기본
구성요소 배치 직후의 값이고, 메뉴 설치 직후에는 76바이트가 남는다.
최종 이미지에서는 `CA3A8..CA3C4`의 대사 코드 28바이트와
`CA3C4..CA3F4`의 기술 설명 코드 48바이트가 이 공간을 모두 차지한다.
이 공간을 새 코드에 할당하지 않았다. 링커는 이후 쓰기까지 합산한
`final_arena_tail`을 별도로 기록하며, 이 후보의 최종 미배정 꼬리 공간은
0바이트다. 같은 값을 쓰는 영역도 점유로 세고 겹친 영역은 중복 합산하지
않는다. 중간 단계의 `free` 값이나 0으로 채워진 바이트만으로 새 배치를
승인하지 않는다.
