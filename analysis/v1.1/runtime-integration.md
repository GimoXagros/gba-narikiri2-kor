## 주소·데이터 보존

기존 10,172개 바인딩의 저장 위치·원래 포인터 값과 문자열 시작 9,246곳을
유지한다. 추가 UI 197개는 별도 집계한다. 채택한 한국어 바이트·공유 변형,
저장 레코드와 파일 형식도 변경하지 않는다.

실제 후보 코드를 8MiB ROM만 매핑한 CPU 환경에서 실행하여 기존 10,172개와
추가 UI 197개의 복원 바이트를 확인했다. 불일치와 출력 경계 침범은 0건이다.
공유 변형 선택값은 검사 코드가 제공하므로 자연 진행 중의 선택 검증은 별도다.

폰트·타이틀·시작 안내·엔딩·지도 자원은 카트리지 내부에 배치한다. 제한된
독립 참조 검사는 PC 상대 로드 69곳, 기존 훅 23곳, 상대 자원 23개, 부호 있는
지도 참조 22개와 추가 어댑터의 호출·리터럴을 확인한다. 주소처럼 보이는
압축 데이터는 실제 포인터와 구분한다. 계산된 참조 전체의 도달 가능성을
증명한 것은 아니다.

추가로 타이틀·지도·상점의 세 자원표 전체 242개를 후보 ROM의 원래 조회
함수 080033FC로 실행했다. 반환 주소와 보존 레지스터가 모두 일치하며,
자원 주소는 8MiB 범위 안이다. 227개 압축 자원의 해제 결과는 채택본과
동일하다. 압축 자원이 아닌 13개는 일본어 원본·채택본·후보의 주소와
바이트 범위가 모두 같다. 채택본부터 엄격한 RL 검사에 걸리는 2개는
채택본의 주소·바이트를 유지하며, 일본어 원본과 동일한 데이터라고
주장하지 않는다. 이 15개를 압축 해제 통과로 집계하지 않는다.
마지막 상점 팔레트는 실제 0801496E 호출을
실행하여 CpuSet의 원본 주소·제어값과 192바이트 읽기 범위를 확인했다.

기존 코드 000000..0AC3F4의 Thumb PC 상대 로드 후보도 다시 조사했다.
8MiB를 넘는 값 9건은 명령과 리터럴이 모두 일본어 원본부터 동일하다.
새로 남은 확장 영역 참조는 이 제한된 검사에서 없었다. 이 결과는 계산된
주소·간접 호출·다른 코드 영역 전체에 대한 증명을 대신하지 않는다.

같은 후보의 실제 글꼴 코드를 8MiB만 매핑한 CPU에서 실행했다. 큰 글자

해석과 글리프 생성을 실행하되 동기 타일 캐시 진입에서 소비 데이터를
대조했다. 캐시 할당과 화면 출력의 검증은 별도이며 이 검사의 통과로
생략하지 않는다.

독립 검수자가 위 두 검사 소스를 재검토하고 결과 JSON의 동일성을
확인했다. 실제 CPU 메모리 접근도 관측하여 자원 조회 488회 읽기,
글꼴 166,617회 ROM 읽기와 94,000회 쓰기에서 8MiB 밖 읽기 또는 지정한
스택·출력 범위 밖 쓰기가 없음을 확인했다. 자원의 BIOS 압축 해제와
글꼴 캐시 할당까지 이 관측 범위에 포함한 것은 아니다.

입력·선택·페이지 진행 전체를 검사한 것으로 확대하지 않는다.

금지된 이름·빈 이름을 화면에서 재입력하는 경로는 별도 확인 범위다.

## 저장 검증 정정

이전 3abc 및 d5 후보에서 앞 2명, 120바이트만 비교한 결과는 4명 전체의
저장 안전성을 입증하지 못했다. 뒤 2명의 이름에 압축 바이트가 저장되는
오류를 추가 확인했으므로 당시 이름·저장 결과를 완전 통과로 해석해서는
안 된다. 해당 개발 중 SAV는 최종 제공용으로 사용하지 않는다.

현재 ac0ad359 후보에서 새 게임 기본 이름 55,503프레임, 혼합 이름
71,788프레임을 상태 불러오기·RAM 수정 없이 진행했다. 일반 저장 후 새
프로세스로 다시 시작하여 프로필 4개 240바이트, 8개 이름 필드, 인벤토리
원시 데이터 79바이트를 채택본과 비교해 일치를 확인했다. 원본 사용자 SAV도 복사본으로
불러오기·게임 내 재저장·새 프로세스 재로드를 확인했다. 재저장 SHA-256은
`febeda7db5ad19559496ef8827e490ec50ad565fb75a82ec823fc9112ca105b3`이며
원본 입력은 보존했다. 이 세 저장의 인벤토리 바이트는 모두 0이므로 보유품
보존의 근거로 사용하지 않는다.

기존 중단 저장에서는 실제 전투·큐어 사용까지 RAM 수정 없이 진행했고,
인벤토리 원시 데이터 79바이트가 채택본과 동일했다. 이어서
자연 조작으로 저장 가능한 월드에 복귀하여 일반 저장을 완료했다. 두
ROM의 8,192바이트 SAV SHA-256이 모두
`db10b08113849b05b3fa392da487816457e9cfa89fabaabc2d430138bdec4f6e`로
동일했다. 기존 실행을 완전히 종료한 뒤 각 ROM을 별도 프로세스에서
두 번씩 불러왔다. 프로필 4개 240바이트·이름 8개·인벤토리 79바이트뿐 아니라
저장된 게임 데이터 0xA7B바이트 전체와 필드·파티 화면 8회 대조도 모두
일치했다. 모든 종류를 보유한 시험이나 실기 결과는 아니다.

이전 기록의 ‘79개 수량 필드·총 97개’는 저장 바이트를 각각 정수 수량으로
해석한 오류다. 실제 게임의 수량 조회 함수에 ID 0..157을 두 ROM 각각
입력하여 유효 ID 1..156의 수량이 4비트씩 저장되는 것을 확인했다.
새 프로세스로 불러와 실제 아이템 목록에서 확인한 보유량은
지갑 1개·곡괭이 1개·변신 지팡이 3개·빵 1개·프라이팬 1개로 5종 7개이며,
채택본과 ac0 후보의 화면이 같다. 원시 바이트 보존과 저장·재로드 결과는
유효하며, 수량 해석을 이와 구분한다.

생성 경로의 0..21 범위는 직접 호출·콜백 바인딩·원래 생성 루프로 확인했으며
전역 간접 쓰기 증명은 아니다. getter 전체 범위를 생성 범위로 가정하지
않는다. 생성 범위 밖 22/24/55의 긴 이름은 13바이트를 넘으므로 거부한다.

최종 ROM 해시 선택 후 자연 저장·완전 종료 후 재로드·중단 저장을 다시
묶어서 확인한다. 이전 d5 후보의 SGM 3개와 대사집은 해당 해시의 과거
검사 자료다. 최종 SAV/SGM과 10,371행 대사집을 새 후보로 재생성해야 한다.

## 현재 후보의 실제 화면 대조

ac0 후보의 펍 로즈 31페이지·재입장·후속 3페이지를 7,179프레임 동안
진행했다. 37장 중 36장은 채택본과 전체 픽셀이 같고, 나머지 한 장의
차이 31픽셀은 우하단 진행 삼각형에 한정됐다. 주변 33프레임에서 16장은
전체가 같으며 나머지는 같은 31픽셀만 다르다. 글자와 인물은 동일하고,
깜박임 차이를 만드는 정확한 타이밍 원인은 아직 확정하지 않았다.

기존 중단 저장에서 전투로 진입해 민트를 직접 조작하여 큐어를 사용했다.
실제 알림의 BG0 글자와 OBJ 테두리·채움 2,356픽셀, 관련 타일·팔레트는
채택본과 동일했다. 나머지 138픽셀 차이는 알림이 투명한 부분 뒤 배경이다.
배경 가로 스크롤 값 41/39 차이를 확인했으며 전체 전투 영상 일치는
주장하지 않는다. 이 검사는 실제 기술명 표시 한 경로이고, 기술 전체의
자연 습득·사용 검증은 별도다.

부팅 안내·타이틀은 자연 입력 경로로, 엔딩은 공개한 4바이트 시작 분기

검사도 보강해 실제 전체를 재실행했다. 체크섬 알고리즘의 모든 오류나 임의의
손상 파일·강제 저장까지 안전하다는 주장은 하지 않는다.

## 2026-10-11 성능 통합과 최종 이미지 주소 검사

ca83 후보는 여섯 코드 영역 합계 2,006바이트 안에서만 1,738바이트를 변경한다.
그 밖의 변경은 0이며 기존 텍스트 포인터 10,172개·시작 9,246곳·한국어 복원값을
최종 이미지에서 다시 검사해 모두 일치했다. 새 ROM/RAM 공간이나 저장 필드는
추가하지 않았다. 마지막 상점 자원·이름 비교 코드·인접 대사 코드는 그대로다.

실제 분기 163개·명령 813개·PC 상대 읽기 41곳과 고정 배치 52항목을 검사했다.
새 타일 코드의 연속 변수 읽기는 0300004C부터 03000058 직전까지 정확히
12바이트를 r1/r2/r3으로 읽는다. 검사기는 물리적 준비 명령·소비 명령과 분기의
우회를 확인하며, 네 번째 단어 읽기·다른 기반 레지스터·준비 명령을 건너뛰는
변조본을 거부한다. 기존 개별 읽기 방식도 유지하여 이전 후보 검사와 대조했다.
공개 회귀 23개가 최적화 실행 옵션 `-O`에서도 통과했고, 실제 ca83 변조 사본
11개를 거부했다. 이는 명시한 읽기·분기·소유 영역의 검사 범위이다.

같은 ROM·코어·저장·입력으로 여섯 경로를 각각 5회 측정했다. 이전과 같은
`sorted(intervals)[floor((N-1)*0.99)]`를 사용하며 긴 구간도 제외하지 않았다.

RL 전용 소비자 조사에서는 1D6B8/1DBDC가 선택한 원래 레코드를 따라 2E53C의
실제 저장 명령까지 실행했다. 의상 ID 0..201과 몬스터 0..165의 368건을
일본어·채택본·ac0·ca83에서 대조해 주소와 결과가 같았다. 할당 함수만 보호된
시험 객체를 반환하도록 대체했다. 네 이미지 모두 ROM 읽기 5,311회와 쓰기
15,742회에서 허용 범위 침범이 없었다. 이 범위의 기술자 표는 지도 380F08을
선택하지 않았다. 모든 상위 ID·객체 수명 중 쓰기나 지도 32번의 형식 변경을
승인한 결과는 아니며 기존 RL 바이트는 계속 유지한다.

## 남은 관문 — 현재 범위

필수 소비자·계산 참조의 범위 확정, 최종 해시에서 공유 7그룹의 원래 호출자 선택·재개 재검증,
최종 해시의 저장·화면·입력 회귀, 최종 대사집과 SAV/SGM,
실기 및 공개 소스·패키지 검사가 남아 있다. 이전 v1.0 실기 기록은 이번
ROM의 실기 검증으로 전용하지 않는다. 알려진 오류가 있는 이전 후보를
완성본으로 제공하지 않으며 G0~G10 충족 전에 정식 배포하지 않는다.
